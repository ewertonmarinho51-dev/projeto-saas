# Incremento G2: índice, importação e restauração

Registro anterior ao código. Responsável único: `DocumentoService`, usando as tabelas, CAS, RLS e RPC privada documentais existentes. Não cria autenticação, storage ou fonte documental paralelos.

Cada nova revisão guarda atomicamente bytes do checkpoint, índice derivado serializado com hash e modo de construção, build validador e eventual referência de restauração. O índice continua projeção descartável: os bytes nativos são autoritativos. IDs persistem somente pela reconciliação conservadora de `wordcraft_blocos` quando o build coincide; índice antigo ausente ou build diferente exige reconstrução explícita, com novos IDs e invalidação dos anteriores conhecidos. Linhas históricas permanecem sem índice quando ele não foi registrado.

Importação inicial de DOCX conserva no mesmo registro privado os bytes originais e seu SHA-256, além do relatório de conversão. Markdown é lido de `processos.documentos` pelo cliente autenticado, preservado byte a byte, convertido por `export.gerar_docx` com o título de `DOCUMENTOS`, e importado pelo motor pinado. A conversão declara fidelidade pendente; não altera o original no processo, não migra lote e não ativa consumidor operacional.

Restauração lê uma revisão autorizada antiga e grava uma nova revisão com CAS, operação idempotente e `restored_from_revision`. Não reduz a revisão corrente, não modifica história nem permite escrever em documento aprovado/emitido. O índice resultante deriva da revisão corrente para a revisão nova, não copia IDs antigos como se a continuidade fosse provada.

Novos campos ficam na tabela imutável de revisões existente, evitando segundo acervo e preservando suas políticas de leitura. A assinatura RPC antiga será removida atomicamente; argumentos extras só podem vir do owner, não de eventos do editor/JWT. Retry deve correlacionar bytes, build, índice, original, relatório e referência restaurada. Uma falha de CAS deve reverter todos esses campos na mesma transação.

Arquivos previstos: migration gerada pela CLI; owner e seus testes; codec fechado de índice em `wordcraft_blocos` e testes; sequência do harness e inventário RPC. Nenhuma migration anterior será editada. Provas usarão bancos novos descartáveis do loopback, sem aplicar ao laboratório vivo ou remotamente. Este incremento não encerra G2: armazenamento/retensão definitiva, snapshots institucionais e integração operacional continuam sujeitos aos gates.

Implementação: `20261015122441_documentos_editor_persistencia_g2.sql`, gerada pela CLI. A assinatura anterior de nove argumentos é removida e a nova RPC exige dezesseis, mantendo EXECUTE somente para service_role e SECURITY INVOKER. O índice é bytea JSON de codec fechado, com hash de seus bytes exatos; o banco verifica vínculo com documento/revisão/hash/build e o owner valida sua projeção pelo motor. Históricos sem índice continuam NULL; um CHECK NOT VALID exige índice em toda inserção futura. Não houve criação de tabelas nem novo mecanismo de RLS.

APIs novas do owner: `abrir_revisao`, `importar_legado`, `original` e `restaurar`. Importação Markdown não aceita Markdown livre do componente: lê o original autorizado do processo. DOCX recebe bytes do upload e chama o importador nativo com preflight existente. Ambos congelam original e relatório no commit inicial. Após commit confirmado, retry lê o checkpoint já registrado, evitando reconversão e a dependência dos timestamps do ZIP DOCX; os metadados continuam correlacionados pela RPC. Falha de importação não grava revisão nem remove o original no processo/arquivo de entrada.

Resultado executado: 410 testes passaram e 126 integrações externas não configuradas ficaram em skip, combinando owner, codec, SQL real, contenção e trilha. As provas cobrem índice/original imutáveis, ACL de leitura e negação de INSERT do usuário, upgrade sobre história sem índice, reconstrução após mudança de build, CAS concorrente/stale, restauração como nova revisão, retry com original/relatório/índice/referência divergentes e título real do exportador Markdown existente. A validação nativa dos testes Python do owner é explicitamente isolada por stubs; uso com bundle real continua sendo prova separada, dependente do build que expõe `import_docx`.

Advisors oficiais após schema completo em outro banco novo descartável: exit 0, 16 avisos do schema-base; nenhum identifica documentos_editor/documento_editor. Não constitui certificação global de segurança. Todos os bancos próprios dos ensaios foram descartados; não se aplicou esta migration ao laboratório vivo ou remotamente.
